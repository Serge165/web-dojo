# HTML Page Template — Canonical Export Structure

> **Purpose:** This document defines the canonical HTML structure that every exported page
> (standalone, clean export, or multi-page bundle) must follow. The parser/importer should
> expect this shape when scanning exported files, and code generators should produce markup
> that matches it.
>
> The actual output is produced by `frontend/src/lib/exportHtml.js` (frontend export paths)
> and `backend/server.py::_project_to_html` (preview/publish). Both are kept in sync.

---

## 1. Full Page Skeleton

```html
<!doctype html>
<html lang="en">
<head>
  <!-- 1. REQUIRED: Charset + Viewport -->
  <meta charset="utf-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1" />

  <!-- 2. REQUIRED: Page title -->
  <title>%%pageName%% — %%pageType%%</title>

  <!-- 3. SEO meta tags (optional, generated by buildSeoMeta) -->
  %%seoMetaTags%%

  <!-- 4. JSON-LD structured data (optional, generated by buildJsonLd) -->
  %%jsonLdStructuredData%%

  <!-- 5. Google Fonts links (optional, generated by buildFontLinks) -->
  %%googleFontLinks%%

  <!-- 6. User head content / CDN embeds / analytics snippets -->
  %%remainingHeadContent%%

  <!-- 7. REQUIRED: Link to globals.css (always last in <head>) -->
  <link rel="stylesheet" href="globals.css" />
</head>

<body
  data-wd-project="%%projectId%%"
  data-wd-page="%%pageSlug%%"
  data-wd-page-type="%%pageType%%"
>
  <!-- 8. REQUIRED: Project ID bootstrap script (body top, not <head>) -->
  <script>window.__WD_PROJECT_ID=window.__WD_PROJECT_ID||document.body.getAttribute("data-wd-project")||"";</script>

  <!-- 9. OPTIONAL: Template header wrapper (when use_template = true) -->
  %%templateHeaderHtml%%

  <!--
    10. PAGE CONTENT: Classed block HTML
    
    Semantic path (data-wd-cat + data-wd-block stamped):
      <section class="block block-<catId>-<slug>-<occ> block-<catId>-<slug>">
    
    Legacy fallback path (no data-wd-* pair):
      <section class="<tag>-<n>">
  -->
  %%pageBlocksHtml%%

  <!-- 11. OPTIONAL: Template footer wrapper -->
  %%templateFooterHtml%%

  <!-- 12. OPTIONAL: Custom JS (before </body>, escRawScript applied) -->
  <script>%%customJavaScript%%</script>
</body>
</html>
```

## 2. Block Class Naming Reference

### 2a. Semantic Path (data-wd-cat + data-wd-block stamped)
```
class="block block-<catId>-<slug>-<occ> block-<catId>-<slug>"
                       |                       |
                       |                       +-- Shared marker (GEMS hook)
                       +-- Per-occurrence suffixed class (page-prefixed in multi-page)
```

### 2b. Legacy Fallback Path (no data-wd-* pair)
```
class="<tag>-<n>"
```

## 3. File Structure (Multi-Page Export)
```
site/
  index.html        # Each page gets its own .html file
  about.html
  contact.html
  globals.css       # Single shared stylesheet
  js/
    main.js         # Deduplicated script files (data-forge-js)
  imgs/
    .keep           # Placeholder for user-uploaded images
  fonts/
    .keep           # Placeholder for uploaded font files
```

---

## 4. Key Constraints

1. **No inline `style=""` on any block element** in exported output.
2. **No `<style>` tags in `<head>`** from forge-managed CSS.
3. **No `__WD_PROJECT_ID` bootstrap in `<head>`.** Rides on `<body data-wd-project>`.
4. **`globals.css` link is always the last element in `<head>`.**
5. **Custom JS is always the last element before `</body>`.**
6. **Semantic `<header>`, `<main>`, `<footer>` tags preferred** but not enforced.
